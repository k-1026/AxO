> 아래 팀 규칙의 `research/`, `idea/`, `.claude/`, `run_log.jsonl` 등 경로는 저장소 최상위 기준입니다. 공통 자동 적용 규칙은 최상위 동명 파일을 사용합니다.

# CLAUDE.md

이 저장소는 대구 약전골목 한방 뷰티 브랜드 AI 에이전트를 위한 **팀 자료조사 저장소**예요.
여기 쌓인 조사는 나중에 에이전트가 읽는 지식 파일이 되므로, 아래 규칙을 반드시 지켜 주세요.
팀 규칙 전체는 `README.md`에 있어요.

## 기획 절차 (`playbook.md`)

기획·사업 타당성 분석·출시 기획안·계획서·결과보고서 작업은 **항상 `playbook.md`를 먼저 읽고 그 절차대로** 해요.

- 작업을 시작할 때 이번 요청이 playbook의 **몇 단계**(1~13)에 해당하는지 먼저 밝혀요.
- 단계마다 playbook의 세 항목을 따라요: **1. 무엇을 구하나 → 2. 필요한 입력 → 3. 타당한지 확인하는 방법**. 3번 확인을 통과하지 못하면 다음 단계로 넘어가지 않고, 무엇이 막혔는지 알려요.
- 앞 단계 결과가 없으면 지어내지 말고 그 단계부터 하거나 `[확인필요]`로 표시해요. 단계를 건너뛰면 이유를 적어요.
- 결과에는 "N단계 확인 결과: 통과 / 미통과 (이유)"를 함께 적어요.
- 서브에이전트(`.claude/agents/`)는 맡은 단계가 정해져 있어요.

  | 에이전트 | 맡는 단계 |
  |---|---|
  | `researcher` | 2 자료 수집, 3 가정의 근거, 4 시장 규모 입력값 |
  | `competitor-analyzer` | 5 경쟁 비교, 6 포지셔닝, 12 우선순위 점수의 근거 |
  | `model-simulator` | 3 가정 세우기, 7 단위경제 ~ 11 민감도 (엑셀 계산) |
  | `reviewer` | 모든 단계의 "타당한지 확인하는 방법" 점검, 13 결론 심사 |

- playbook과 이 파일의 규칙이 부딪히면 이 파일(CLAUDE.md)이 우선이에요. playbook을 고치면 이 섹션과 `AGENTS.md`도 함께 확인해요.

### 단계별 로그 (`run_log.jsonl`)

playbook 단계를 하나 끝낼 때마다(통과·미통과·건너뜀 모두) 저장소 맨 위 `run_log.jsonl`에 기록을 하나 추가해요. **JSON Lines 형식**이라 한 줄에 기록(JSON 객체) 하나를 쓰고, 기록 안에서는 줄을 바꾸지 않아요. 새 기록은 파일 맨 끝에 한 줄로 덧붙이고, 파일이 없으면 새로 만들어요. 인코딩은 UTF-8이고, 이 파일은 커밋해요.

| 항목 | 내용 |
|---|---|
| `run_id` | 기획 한 건을 묶는 이름 (예: `"2026-11-16_한방기초라인"`) |
| `step`, `step_name` | playbook 단계 번호와 이름 |
| `timestamp` | 기록한 시각 (`YYYY-MM-DDThh:mm:ss+09:00`) |
| `actor` | 누가 했나: `main`, 서브에이전트 이름, 또는 팀원 브랜치명(`MEJ` 등) |
| `request` | 이번 작업 요청 한 줄 |
| `inputs` | 쓴 입력값 목록: `{"cell": "가정!D12", "value": 800, "구분": "가정"}` |
| `outputs` | 결과값과 칸, 보수·기준·낙관 모두: `{"cell": "손익!B9:D9", "보수": …, "기준": …, "낙관": …}` |
| `checks` | playbook "타당한지 확인" 항목별 결과: `{"항목": …, "결과": "통과/미통과", "메모": …}` |
| `status` | `"통과"` / `"미통과"` / `"건너뜀"`, 그리고 `status_reason` |
| `assumptions_used` | 기댄 '가정' 구분 값의 칸 목록 |
| `unknowns` | `[확인필요]`·`미확인` 항목 |
| `files_changed`, `commit` | 바뀐 파일과 커밋 해시 (커밋 전이면 `null`) |
| `next` | 다음 단계나 막힌 점 |

- reviewer 기록은 `verdict`(가 / 부 / 조건부 시행)를 따로 적고, 지적사항은 `checks`에 `심각도`(치명/보완/참고)·`위치`·`고치는 방법`을 함께 적어요. 대시보드(`dashboard/`)의 리뷰 지적사항 목록이 이 칸을 읽어요.
- **쌓기만 해요.** 지난 줄은 고치거나 지우지 않아요. 틀렸으면 새 기록에 `"corrects": 고칠 기록의 줄 번호(1부터)`를 붙여요.
- **숫자는 칸과 함께** 적어요. 엑셀 칸이 없는 숫자는 `[확인필요]`로 `unknowns`에 넣어요.
- **결과는 세 시나리오를 모두** 적어요. 불리한 결과도 빼지 않아요.
- 이름·연락처 같은 **개인정보는 적지 않아요.**
- 기록 후 모든 줄이 올바른 JSON인지 확인해요 (예: `python -c "import json; [json.loads(l) for l in open('run_log.jsonl', encoding='utf-8') if l.strip()]"`).

## 브랜치

- 팀원은 자기 브랜치(`HSJ`, `LJH`, `MEJ`)에서만 작업해요. `research`, `main`에 직접 커밋·push하지 않아요.
- 작업 전 최신 조사는 `git pull origin research`로 받아요 (main 아님).
- PR의 base는 항상 `research`예요.
- 커밋 메시지 형식: `[브랜치명] 한 일` (예: `[LJH] 당귀 산지 조사 추가`)

## 조사 파일 작성

- 새 조사는 `research/_template.md`를 **복사**해서 `research/내이름_주제.md`로 만들어요. `_template.md` 원본은 수정하지 않아요.
- 양식의 섹션 순서와 머리말(담당·영역·주제·최종수정·상태)을 그대로 지켜요.
- 핵심 내용의 모든 문장 앞에 `[사실]` / `[해석]` / `[아이디어]` 중 하나를 붙여요. 출처로 확인되지 않은 것은 `[사실]`로 쓰지 않아요.
- 원문을 복사하지 말고 요약해요. 인용은 꼭 필요할 때 짧게 따옴표로만.
- 약재 이름은 `한글(한자)`로 통일해요 (예: 당귀(當歸)). 새 용어는 `research/glossary.md`에 추가해요.

## 출처 규칙

- 출처 없는 내용은 쓰지 않아요. 문장 끝에 `[1]` 번호를 달고 파일 아래 출처 표에 같은 번호로 적어요.
- 출처 형식과 등급 기준은 `research/_template.md`의 출처 주석(①~④)을 따라요.
  - 🟢 정부·기관·박물관·논문·국가 DB
  - 🟡 언론 기사·기업 공식 자료·책·인터뷰
  - 🔴 블로그·SNS·유튜브·나무위키·AI 답변 → 핵심 사실의 근거로 쓰지 않고 🟢🟡 출처를 다시 찾아요
- 연도·인물·제도명·약재 효능은 출처 2곳 이상으로 교차확인하고, 출처끼리 다르면 `❗충돌`로 표시한 뒤 "❓ 아직 모르는 것"에 추가해요.
- 확인일(실제로 본 날)을 적고, 논문·보고서는 쪽수까지 적어요.
- **출처를 지어내지 않아요.** URL·저자·쪽수를 확인할 수 없으면 비워 두고 "확인 필요"라고 적어요.
- 이미지는 `research/assets/`에 저장하고 사용 가능 여부(✅ / ⚠️ / ❌)를 표시해요.
- 출처 등급을 매길 때는 `prompts/source-grading-prompt.md`의 기준과 출력 형식을 따라요.

## 계획서·결과보고서 작성 (엑셀 모델 기준)

기준 엑셀: `idea/market_model_case_AxO.xlsx`

1. 계획서의 모든 숫자는 엑셀에서 가져와요. 숫자마다 어느 시트·칸에서 왔는지 알 수 있게 적어요 (예: `손익!C9`).
2. '가정' 시트에서 구분이 '가정'인 값을 쓸 때는 결과보고서 본문에도 "가정"이라고 밝혀요.
3. 엑셀에 없는 내용은 지어내지 말고 `[확인필요]`라고 표시해요.
4. 불리한 숫자를 빼거나 낙관 시나리오만 적용하지 않아요. 보수·기준·낙관을 함께 보여 줘요.
5. 결론은 '가', '부', '조건부 시행' 중 하나로 내요. 조건부 시행이면 조건을 함께 적어요.
6. 자료를 수집할 때는 값·기준 시점·출처·URL을 함께 적어요. 찾지 못한 항목은 '미확인'으로 남겨요.
7. 가정은 보수·기준·낙관 세 값으로 제안해요.
8. 계산은 반드시 엑셀 수식을 걸어서 해요. 계산 결과를 숫자로 직접 입력하지 않아요.
