# 📢 AxO 발표자료 (`presentation` 브랜치)

> 이 브랜치는 **발표자료만 올리는 곳**이에요.
> 조사·기획 작업은 각자 브랜치(`HSJ`, `LJH`, `MEJ`)에서 하고, 발표에 쓰는 최종 자료만 여기에 올려요.

> ⚠️ **올리기 전에 이 README를 먼저 끝까지 읽어요.**
> 각자 브랜치의 작업물을 `presentation` 브랜치로 올릴 때마다, 먼저 `git pull origin presentation`으로 최신 README를 받아 읽고 아래 규칙과 순서대로 올려요. AI(Claude Code 등)로 올릴 때도 AI에게 이 README를 먼저 읽게 해요.

---

## 1. 📁 폴더 규칙

| 규칙 | 내용 |
|---|---|
| 폴더 이름 | 발표 날짜로 `yyyy-mm-dd` 형식 (예: `2026-11-18`) |
| 날짜당 폴더 | **같은 날짜 폴더는 하나만** 만들어요. 그날 발표자료는 모두 그 폴더에 넣어요 |
| 올리는 것 | 발표에 실제로 쓰는 자료: 슬라이드(`.pptx`, `.pdf`), 발표용 HTML과 그 이미지, 발표 가이드 |
| 올리지 않는 것 | 조사 문서, 원자료(CSV·엑셀), 작업 중인 초안, 개인 메모 |
| 맨 위 폴더 | `README.md`와 날짜 폴더만 둬요 |

- HTML 발표자료가 쓰는 이미지는 **같은 날짜 폴더 안의 `image/` 폴더**에 모아 넣어요. 이미지 파일이 날짜 폴더에 흩어지지 않게 해요.
  - HTML 안의 이미지 경로도 `image/파일이름.png`로 맞춰요. 다른 폴더를 가리키면 이 브랜치에서 이미지가 깨져요.

  ```
  2026-11-18/
  ├── AxO_피치_7장.html
  ├── AxO_피치_7장.pptx
  └── image/
      ├── positioning_map.png
      └── user_flow.png
  ```
- 파일 이름은 무엇인지 알 수 있게 써요 (예: `AxO_피치_7장.pptx`). 같은 이름의 최종본이 여러 개면 `_v2`처럼 구분해요.

## 3. 🔁 올리는 순서

```bash
# ① 내 브랜치에서 작업하고 내 브랜치에 커밋·push
git switch HSJ                       # 자기 브랜치 이름으로
git add .
git commit -m "[HSJ] 11/18 피치 자료 작성"
git push origin HSJ

# ② presentation 브랜치로 이동해서 최신 상태 받고, README.md 먼저 읽기
git switch presentation
git pull origin presentation
#    → README.md를 열어 폴더 규칙·체크리스트 확인

# ③ 날짜 폴더에 발표용 자료만 넣기 (폴더가 이미 있으면 그 안에 추가)
#    예: 2026-11-18/AxO_피치_7장.pptx
#    → README.md 2장 "지금 있는 발표자료" 목록도 고치기 (새 폴더·새 자료 반영)

# ④ 발표 자료와 README만 골라서 커밋·push
git add 2026-11-18 README.md
git commit -m "[HSJ] 11/18 피치 발표자료 추가"
git push origin presentation
```

- `git add .` 대신 **날짜 폴더와 README.md만** `git add` 해요. 작업 중인 다른 파일이 같이 올라가지 않게요.
- 브랜치를 옮길 때 커밋 안 한 파일 때문에 막히면, 먼저 내 브랜치에 커밋하거나 그 파일을 옮긴 뒤 다시 시도해요.

- [ ] HTML이 쓰는 이미지가 같은 날짜 폴더의 `image/` 폴더에 모여 있고, HTML 경로도 `image/`를 가리키나요?
- [ ] README.md 2장 "지금 있는 발표자료" 목록을 고쳤나요?
- [ ] 커밋 메시지가 `[브랜치명] 한 일` 형식인가요?
