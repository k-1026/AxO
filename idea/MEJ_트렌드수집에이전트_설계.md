# 트렌드 수집 에이전트 시안

> 관련 파일
> - 수집 스크립트 초안: [trend/datalab_collect.js](trend/datalab_collect.js)
> - 검색어 묶음: [trend/keywords.json](trend/keywords.json)
> - 결과를 읽는 화면: [MEJ_K9_결과화면_버튼가중치_시안.html](MEJ_K9_결과화면_버튼가중치_시안.html)의 '📈 뜨는 원료' 버튼

## 📌 한 줄 요약
지식 파일은 과거 조사라서, 매주 최신 검색 흐름을 모아 "트렌드 스냅샷" 파일로 갱신하는 서브 에이전트를 붙이고, 메인 에이전트는 이 파일을 '📈 뜨는 원료' 점수로만 써요.

## 🔑 핵심 내용
- [해석] 메인 에이전트가 읽는 지식 파일(K2~K6 등)은 조사한 날의 자료라 최근 흐름을 반영하지 못해요.
- [아이디어] 그래서 두 층 구조로 나눠요.
  - **바뀌지 않는 층:** 지식 파일 (원료 규제, 가격 기준, 광고 표현 규칙)
  - **매주 바뀌는 층:** 트렌드 스냅샷 (검색 흐름, 기능성 보고 증가, 업계 기사)
- [사실] 네이버 데이터랩 검색어 트렌드는 주간 단위(`week`)로 조회할 수 있어요. 한 요청에 검색어 묶음을 최대 5개 넣을 수 있고, 값은 검색 횟수가 아니라 구간 안의 상대 지수예요 [1]
- [해석] 상대 지수라서 약재끼리 크기를 비교하지 않고, 같은 약재 안의 **"최근 4주 ÷ 그 전 12주"** 변화만 판정해요.
- [아이디어] 판정은 체크리스트 규칙을 따라요. 자료가 없거나 오래되면 점수를 비워 두고(null), 화면에서는 점수 범위와 근거 확보 비중으로 보여 줘요.

## 1. 구조
```
[트렌드 수집 에이전트]  매주 월요일 1회
  ① 수집 → ② 정리·출처 표시 → ③ 변화 판정 → ④ idea/trend/trend.json + 트렌드스냅샷_YYYY-MM-DD.md 저장
                                                                  ↓
[메인 에이전트]  계절 선택 → 피부 고민 → 라인 후보 → 필수 통과 조건 → 버튼 가중치 순위
                                                        ('📈 뜨는 원료' 버튼이 trend.json을 읽음)
```

## 2. 무엇을 모으나
| 자료 | 알 수 있는 것 | 수집 방법 | 등급 | 출시 순위에 쓰는 법 |
|---|---|---|---|---|
| 네이버 데이터랩 검색어 트렌드 | 약재 화장품 검색 흐름 | 공식 오픈 API (2단계 스크립트) | 🟢 | 📈 뜨는 원료 점수 |
| 의약품안전나라 기능성화장품 보고 목록 | 약재별 기능성 제품 증가 | 공개 목록 조회 (주 1회) | 🟢 | 🎯 기능성 경쟁 점수 |
| 업계 기사 (장업신문 등) | 신제품·원료 화제 | 기사 검색, 원문 복사 없이 요약 | 🟡 | 상세 화면 "최근 소식" 참고 |
| 올리브영·화해 랭킹 | 잘 팔리는 피부 목적 | 이용약관상 자동 수집이 막힐 수 있어 **팀원이 주 1회 직접 기록** | 🟡 | 🛒 같은 목적 인기 제품 수 |
| 인스타그램·유튜브 | 화제 키워드 | 직접 확인 | 🔴 | 점수에 쓰지 않음, "화제 신호" 칸에만 |

## 3. 판정 규칙 (팀이 정할 값)
| 최근 4주 ÷ 그 전 12주 | 판정 | 📈 뜨는 원료 점수 |
|---|---|---|
| 1.2 이상 | 상승 | 5 |
| 0.8 초과 1.2 미만 | 보통 | 3 |
| 0.8 이하 | 하락 | 1 |
| 두 구간 모두 0 | 자료 없음 | null (확인 필요) |
| 수집일이 30일보다 오래됨 | 오래된 자료 | null (확인 필요) |

- 검색량이 없는 주는 응답에서 빠질 수 있어 0으로 채워요 [2]
- 검색량은 관심의 신호이지 실제 구매가 아니에요. 체크리스트의 "구매 의향을 실제 구매로 취급하지 않는다" 규칙에 따라 '고객 수요'와 따로 둬요.

## 4. 단계별로 만들기
| 단계 | 방법 | 필요한 것 | 상태 |
|---|---|---|---|
| 1단계 | 팀원이 주 1회 데이터랩 웹에서 같은 검색어 묶음을 조회하고, AI가 3번 규칙으로 정리 | 없음 | 바로 가능 |
| 2단계 | `node idea/trend/datalab_collect.js` 로 수집·판정·파일 저장 자동화 | 팀이 네이버 개발자센터에서 직접 발급한 API 키 (환경 변수로만, 커밋 금지) | 스크립트 초안 완료, 실제 호출 전 |
| 3단계 | 매주 월요일 자동 실행 → 파일 갱신 → research 브랜치로 PR | Claude Code 예약 작업 설정 | 2단계 확인 후 |

- 스크립트에서 확인한 것
  - `--self-test`: 판정 계산 4가지(상승·보통·하락·자료 없음) 통과
  - `--dry-run`: 요청 2건 생성 (약재 7개를 5개 + 2개로 나눔)
  - 키 없이 실행하면 안내 메시지를 내고 멈춰요
- 실제 API 응답은 아직 받아 보지 않았어요.

## 5. 서브 에이전트 지시문 (초안)
```
너는 한방 스킨케어 브랜드의 트렌드 수집 에이전트야.
1. idea/trend/keywords.json 의 약재별 검색어 묶음으로 최근 16주 주간 검색 흐름을 수집한다.
2. 약재마다 최근 4주 평균 ÷ 그 전 12주 평균을 계산해 상승(1.2 이상)/보통/하락(0.8 이하)/자료 없음으로 판정한다.
3. 결과를 idea/trend/trend.json 과 트렌드스냅샷_YYYY-MM-DD.md 로 저장한다. 모든 줄에 출처·등급·확인일을 적는다.
4. 출처가 🔴(SNS·블로그)인 내용은 "화제 신호"로만 적고 점수에 넣지 않는다.
5. 수집에 실패하거나 자료가 없으면 점수를 지어내지 말고 null 과 "확인 필요"로 남긴다.
6. 원문을 복사하지 않고 요약한다. "치료", "염증 완화" 같은 의약품식 표현을 쓰지 않는다.
```

## ❓ 아직 모르는 것
- 데이터랩 API 요청 주소, 인증 헤더, 묶음당 검색어 최대 개수(5 / 20으로 자료마다 다름), 하루 호출 한도 → developers.naver.com 공식 문서로 확인 필요 (이 환경에서는 문서를 열지 못했어요)
- 검색어 묶음("오미자 토너" 등)이 약재 화장품 관심을 잘 대표하는지 → 팀 검토
- 판정 기준(1.2 / 0.8)과 오래된 자료 기준(30일) → 팀 결정
- 의약품안전나라 보고 목록을 자동으로 받을 공식 경로가 있는지
