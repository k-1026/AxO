- [해석] 실제 수요, 효율 개선, 경쟁 도구 대비 우위는 검증 전이다. [1]
- [해석] 초기 핵심 기능은 원료 근거 비교, 라인 구성, 기획서 반복 작성 문제에 대응하도록 제안했다. [1][2]

## 3. 첫 버전의 제안 범위

- [아이디어] 기본 흐름은 `기획 조건 입력 → 약재 후보 3개 비교 → 라인 초안 1개 → 개발 의뢰서`로 구성한다. [1]
- [아이디어] 후보 수와 초안 수는 첫 버전의 제안값이며, 자료 부족 시 개수를 채우기 위해 근거 없는 추천을 추가하지 않는다. [1]

| 단계 | 입력·처리 내용 | 산출물 |
|---|---|---|
| [아이디어] 기획 조건 입력 | 계절·타깃 피부 타입·주요 고민·목표 가격대·출시 시점·판매 지역 | 구조화된 기획 조건 [1][2] |
| [아이디어] 후보 비교 | 확인된 자료 범위에서 약재 후보의 적합성과 근거를 비교 | 후보별 출처·선정 이유·근거 부족 표시 [1] |
| [아이디어] 라인 구성 | 제품 역할과 제형 방향, 사용 순서를 제안하고 BM이 선택·수정 | 제품 라인 초안 [1] |
| [아이디어] 의뢰서 정리 | 추천 이유와 제품 구성, 추가 검토 항목을 한 문서에 정리 | 출처가 연결된 개발 의뢰서 [1] |

## 4. 차별화 방향

- [아이디어] `조건 → 원료 → 라인 → 의뢰서`를 연결해 BM의 의사결정 흐름에 맞는 결과물을 제공한다. [1]
- [아이디어] 후보 간 비교와 선정 이유 추적으로 BM이 추천을 수정·설명하기 쉽게 만든다. [1]
- [아이디어] 근거와 추정을 구분하고, 근거가 부족한 조건은 추가 확인 항목으로 남긴다. [1]
- [아이디어] 반복 사용 과정에서 브랜드의 채택·제외 사유를 축적해 다음 시즌의 검토 기준으로 활용한다. [1]

## 5. 개발 준비 및 검토 범위

- [아이디어] 먼저 범위를 정한 약재 근거 자료와 제품 개발 의뢰서 양식을 확보한다. [1]
- [아이디어] 확장 기능은 시장·경쟁사·공급사 자료 확보에 맞춰 구체화한다. [1]
